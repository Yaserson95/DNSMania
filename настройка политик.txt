Используйте код с осторожностью.

4 важных UX-совета для вашего GUI

1. Динамическая валидация Действий (-Action): Если пользователь выбрал уровень «На сервере», варианты ALLOW в GUI должны становиться заблокированными (disabled). Серверные политики Windows Server поддерживают исключительно блокировку — DENY или IGNORE.
2. Удобный конструктор критериев: Не заставляйте пользователя руками писать системную строку вроде EQ,192.168.1.0/24. Сделайте в интерфейсе два раздельных поля: выпадающий список для оператора (Равно (EQ) / Не равно (NE)) и текстовое поле (или список уже существующих подсетей) для самого значения. При сборке команды ваш код сам склеит их через запятую.
3. Поле «Предпросмотр CLI»: Профессиональные системные администраторы обожают, когда GUI-утилиты показывают итоговый PowerShell-скрипт перед выполнением. Добавьте снизу текстовое поле readonly, где в реальном времени будет собираться строка командлета. Это защитит от ошибок и позволит скопировать код для автоматизации.
4. Сетка весов трафика (Zone Scope Weights): Если создается политика ALLOW для балансировки трафика (Geo-DNS), утилита должна позволять добавлять несколько строк областей зон с их весами, например: Разделить трафик: [ scope-EU, 7 ] и [ scope-US, 3 ]. В синтаксисе PowerShell это превратится в единую строку: -ZoneScope "scope-EU,7;scope-US,3".

🛠️ Важные детали реализации этой таблицы для разработчика:

1. Индикаторы действий (Action-колонка):
	• Выделяйте действия цветом. Опытные админы привыкли: ALLOW — зеленый, DENY / IGNORE — красный или оранжевый. Это позволяет мгновенно оценить безопасность конфигурации.
2. Столбец «Приоритет» (Порядок обработки):
	• Стрелочки [ ▲ ] [ ▼ ] в крайней правой колонке должны физически менять порядок строк.
	• Логика под капотом: Если админ нажимает стрелку «Вверх» на 3-й строчке, GUI должен выполнить команду изменения приоритета: Set-DnsServerQueryResolutionPolicy -Name "Redirect_MSK" -ProcessingOrder 2. Сервер Windows сам сдвинет остальные правила вниз.
3. Отображение сложных условий (Мульти-критерии):
	• Обратите внимание на правило №2 (BlockTunneling). В PowerShell это выглядит как два отдельных параметра: -QType "EQ,TXT" -TransportProtocol "EQ,UDP".
	• В таблице выводите их через аккуратный перенос строки с подсветкой оператора связи (И / ИЛИ), который берется из параметра -Condition.
4. Отображение весов балансировки:
	• В правиле №4 показан пример Geo-DNS балансировки. Если для одной политики задано несколько областей (Scopes), выводите их списком с указанием их долей (весов), чтобы админ сразу видел пропорцию распределения трафика (70% на 30%).
